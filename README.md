# WiFi Power Meter

Мониторинг трёхфазной электросети в доме через WiFi-счётчик **HN-PM3F001D** с оповещениями и отчётами в Telegram.

## Возможности

- Опрос счётчика по REST API раз в `MEASUREMENT_INTERVAL` секунд, запись всех параметров в SQLite.
- Оповещения в Telegram о пропадании напряжения, отклонении от нормы и несимметрии фаз.
- Подтверждение реальных обрывов электричества через ИБП (Megatec/Q1 по COM-порту) — чтобы не путать обрыв сети со сбоем WiFi/самого счётчика.
- Отчёты `/day`, `/week`, `/month` (по команде и автопуш по расписанию): потребление, обрывы/отклонения по фазам, время в норме/вне нормы ±10%.
- Погода (текущая + прогноз на завтра) по расписанию и по команде `/weather`.

## Устройство и API

Счётчик HN-PM3F001D отдаёт JSON по `GET http://<DEVICE_IP>/json`:

- `U1..U3`, `I1..I3`, `W1..W3`, `KWH1..KWH3` — напряжение/ток/мощность/энергия по фазам
- `U0/I0/W0/KWH0` — суммарные значения (`KWH0` — накопительный счётчик кВт·ч за всё время)
- `PW*CNT0`, `PWLMSUM0` — внутренние счётчики прибора за сутки/месяц (см. «Особенности» ниже)
- `T1`, `H1`, `WIFI1`, `DATETIME`, `UNIXTIME`, `UPTIME`, `HostName`

## База данных (`power_monitoring.db`)

- **devices** — устройства (id, name, ip_address, model, hostname)
- **measurements** — измерения на каждом опросе: напряжения/токи/мощности по фазам + суммарные, температура/влажность, uptime, wifi_signal, unix_time
- **events** — события: `event_type`, `details` (JSON: фаза, значение, пороги, предыдущее состояние), `notified`, `unix_time`

Типы событий: `power_outage`, `power_restored`, `voltage_deviation`, `voltage_normal`.

## Пороги напряжения

Номинал `VOLTAGE_NOMINAL = 220В` (в `utils.py`; по действующему ГОСТ 32144-2013 — 230В, историческое расхождение).

Работает гистерезис, чтобы не спамить оповещениями на колебания у границы диапазона:

- **Вход** в `deviation` — при выходе за `VOLTAGE_TOLERANCE` (±14%, порог занижен намеренно относительно ГОСТ, чтобы не заваливать частыми короткими скачками).
- **Возврат** в `normal` — только когда напряжение снова внутри более узкого `VOLTAGE_TOLERANCE_NORMAL` (±10%).
- Ниже 10В по любой фазе — `outage` (пропадание).
- Несимметрия между фазами: норма 2%, предел 4% (`VOLTAGE_TOLERANCE_BETWEEN_PHASES[_MAX]`).

Отчёты `/day`, `/week`, `/month` считают время внутри/вне диапазона ±10% напрямую по сырым измерениям (не по событиям — те привязаны к порогу входа 14%, а не к 10%-коридору).

## Telegram-команды

- `/status` — текущее напряжение, мощность, статус ИБП
- `/day` — отчёт за вчера
- `/week` — отчёт за последние 7 дней
- `/month` — отчёт за текущий месяц
- `/weather` — текущая погода + прогноз на завтра
- `/help` — справка по порогам и командам

Отчёты за вчера/неделю/месяц дополнительно приходят автоматически раз в сутки в `REPORT_HOUR:REPORT_MINUTE` (по умолчанию 09:00); погода — по расписанию `WEATHER_SCHEDULE`.

## Запуск

```bash
pip install -r requirements.txt
python main.py
```

Конфигурация (IP устройства, токен бота, ID чатов, ключ погоды, пороги, расписания) — в `utils.py`.

## Особенности / известные нюансы

- **Приложение может работать с перерывами** (перезапуски, отладка) — для расчётов за длительный период предпочтительны счётчики самого прибора (`PWLMSUM0`, `PWLDCNT0` и т.п.), а не дельты по `measurements`, которые занижаются при простоях.
- **Семантика `PW*`-полей прибора неочевидна**: `PWLMSUM0` эмпирически совпадает с потреблением с начала месяца и используется как основной источник в `/month`; `PWCMCNT0` — под наблюдением, реальный смысл не подтверждён; `PWLDCNT0`/`PWPDCNT0` — вчера/позавчера, подтверждено.
- **ИБП по COM-порту**: если сторонний UPS-монитор (например, штатный софт от производителя ИБП) держит тот же COM-порт эксклюзивно, `ups_probe.py` не сможет его открыть (`PermissionError`) — подтверждение обрывов через ИБП тогда не работает, пока порт не освободится.
